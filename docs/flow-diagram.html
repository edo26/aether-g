Alur AETHER-G

Dari sensor di kompartemen sampai saran untuk kru. Status kebakaran selalu diputuskan detektor berbasis aturan dalam hitungan milidetik. Gemma hanya menjelaskan, tidak pernah mengubah status.

Target demo

Satu Jetson, sepenuhnya offline

Semua yang sekarang tersebar di server zerodays dan Mac Mas Heri pindah ke satu Jetson. ESP32-S3 membaca sensor dan mengirim JSON lewat USB. Tidak ada internet, Cloudflare, Dokploy, maupun WireGuard.

Bisa jalan di Jetson?

Bisa. Perubahan kodenya kecil, dan yang paling menentukan adalah model Jetson-nya.

Perubahan yang perlu

  • LLM: oMLX hanya jalan di Mac (MLX), jadi diganti Ollama atau llama.cpp server di Jetson. Keduanya API OpenAI-compatible seperti oMLX, jadi backend cukup ganti AETHER_OMLX_BASE_URL dan AETHER_OMLX_MODEL.
  • Serial bridge: feed.py --stdin sudah ada, tapi perlu dibuat tahan terhadap baris yang bukan JSON (log boot ESP32).
  • Dashboard: build statis dengan VITE_API_BASE diarahkan ke alamat lokal Jetson.
  • Ukur di perangkat: bench_llm.py yang sama bisa dijalankan ke Ollama di Jetson.

Tergantung model Jetson cek dulu

  • Jetson Nano lama (4 GB, JetPack 4): RAM 4 GB dibagi CPU dan GPU dengan InfluxDB dan backend. Paling realistis model Gemma ~1-2B yang dikuantisasi, dan jawabannya kemungkinan sering lewat batas 6 detik, sehingga fallback yang dipakai. Ollama versi baru menargetkan JetPack 5/6, jadi di sini kemungkinan perlu llama.cpp yang di-build sendiri.
  • Jetson Orin Nano (8 GB, JetPack 6): jauh lebih layak. Ollama jalan di GPU, dan Gemma 2B atau E4B 4-bit muat. Kecepatannya tetap lebih lambat daripada Mac, jadi target <2 s untuk advisory lengkap perlu diukur dulu.
  • Kalau RAM mepet, InfluxDB (dibatasi 512 MB) bisa diganti SQLite saja. Ini perubahan di storage layer.
  • Di kedua model, jalur alarm tidak terpengaruh, karena detektornya tidak memakai model.

Yang sudah jalan dan yang belum

Sudah jalan terverifikasi

  • Ingest + detektor di aether-be.fakhrads.dev. Tes smoldering: 151 sampel, 0 error, alarm di t = 10,5 s (CO 26 ppm).
  • Gemma lewat WireGuard: ping ~17 ms, advisory dari deployment benar-benar dari model, bukan fallback.
  • Dashboard live: membaca /status secara polling.
  • Kode backend sudah di-merge ke main (PR #18).

Belum terbuka

  • Panel Gemma di dashboard masih advisory={null} di branch edo, belum membaca /stream atau /advisories.
  • Kualitas jawaban Gemma: tiga langkah isinya sama dan tanpa sumber. Prompt perlu diperbaiki.
  • Jetson asli: sejauh ini deployment baru diuji dengan feed.py.
  • Isolasi tunnel belum dites dari sisi Mac Heri.
